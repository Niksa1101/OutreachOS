# 01 — Campaign CRUD end-to-end

**What to build:** A user can open Video Composer, see a table of their campaigns, create a new one, and rename it. The table shows each campaign's name, recording count, last rendered time, and status.

This is the first vertical slice through the Video Composer module, so it also establishes the pattern every later slice copies: a module-owned router mounted under the existing `/api/v1` tree (inheriting its auth and `redirect_slashes` conventions), the typed API client regenerated from the OpenAPI schema via the existing script, and module screens under the video-composer module directory with no cross-module imports.

The database tables already exist from P0 — no migration is needed.

The status column starts deliberately thin: at this point a campaign is only ever draft-like or has-rendered-before. Ticket 07 makes it reflect validation state and ticket 15 makes it reflect queue activity. Build it as a value the backend computes and the table renders, not as a string assembled in the UI, so those tickets extend it rather than replace it.

**Blocked by:** None — can start immediately.
